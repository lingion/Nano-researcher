# 国内 AI 内测热点采集升级设计

## 目标

将政策/产品采集器从“静态页面 + 普通产品发布”升级为面向中国大陆 AI 早期机会的公开信息雷达，重点发现 2026-04-01 起的灰度、小范围测试、邀请制、候补、内测、公测、开发者预览和公开申请入口。

## 范围与边界

纳入中国大陆厂商、中国区官方页面、官方公告、开发者文档、官方社区、公开报名表、公开论坛和公开社交页面。仅处理公开可访问内容；不绕过登录、验证码、付费墙、访问控制，不抓取私人群组或非公开内容。

## 抓取架构

在现有 Search MCP 与静态 fetch 之后增加分层回退：静态 HTML → SPA/嵌入数据提取 → Playwright 浏览器渲染。每次抓取记录实际使用的渲染模式、最终 URL、日期字段、访问信号、抓取时间和失败原因。浏览器抓取应有超时、资源限制、并发限制和可观测日志，并在不可用时安全回退到现有静态路径。

## 证据模型

扩展 fetched page 记录：published_at、updated_at、last_verified_at、page_render_mode、access_signals、freshness_status、date_evidence、officiality 和 extraction_warnings。日期窗口由任务配置提供；窗口外内容必须排除，日期不明的内容只能作为待核验线索，不能进入有效热点清单。

## 热点目标与排序

查询和 Prompt 优先使用灰度测试、小范围、限量体验、邀请码、候补、内测报名、开发者预览、定向招募、分批开放、早期访问和新功能刚上线等信号。普通发布新闻、泛产品首页和无资格路径内容降权或排除。排序综合近期性、灰度/邀请强度、公开申请可执行性、官方性、稀缺性和大陆可用性，并对普通发布、无日期和无资格路径施加惩罚。

## 数量与最终化

支持 from/to/target 配置，例如 2026-04-01 至当前日期、目标 20 条。只有满足时间窗且有官方或可交叉验证证据的独立热点条目才能计数。数量不足时输出 valid_count、target、shortfall 和原因，不得用普通新闻凑数。最终报告按逐条热点输出，包含产品/功能、测试类型、日期、最近验证时间、状态、入口、邀请码/候补要求、地区、证据和风险。

## 兼容与验证

保留现有 SearchTool/FetchTool 接口，新增浏览器 provider 为可选能力。增加静态页面、JS 页面、Playwright 回退、日期窗口、访问信号、热点排序、数量不足、字段规范化和最终报告测试。运行 TypeScript 检查、相关测试和一次中国大陆热点实测，确认输出不含窗口外条目并正确报告短缺。
