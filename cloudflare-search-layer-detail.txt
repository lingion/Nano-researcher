```js
export function querySchema(extra = {}) {
  const properties = {
    query: { type: 'string', description: 'Search query' },

  };

  if (extra.engines) {
    properties.engines = {
      type: 'array',
      items: { type: 'string' },
```

```js
function mergeSearchAutoResults(collectedResults, limit, query = "") {
  const byUrl = new Map();
  for (const item of collectedResults) {
    const url = String(item?.url || "").trim();
    if (!url) continue;
    const candidate = { ...item, score: scoreSearchAutoResult(item, query) };
    const existing = byUrl.get(url);
    if (!existing || candidate.score > existing.score) {
      ... merge sources ...
      byUrl.set(url, ...)
      continue;
    }
    ... merge sources and increase score ...
  }
  return [...byUrl.values()]
    .sort((a, b) => b.score - a.score || a.rank_within_engine - b.rank_within_engine)
    .slice(0, clampLimit(limit))
    .map(({ score, ...item }) => item);
}
```

- 它会：

  - 保留 sources
  - 多源命中还会给额外权重

十、真正的 search_auto 主函数
==================================================

文件：
- src/index.js

函数：
- searchAuto(args)

位置大约：1676 行

它做的事按顺序是：

1. 选 engines
```js
const engines = selectSearchAutoEngines(args);
```

2. 检测是否有 category
```js
const category = detectSearchAutoCategory(args.query);
const categoryIntent = classifySearchAutoCategoryIntent(category, args.query);
```

3. 如果 category 是 strong，就先跑 category bundle
```js
if (!siteTarget && category && categoryIntent === "strong") {
  const categoryBundle = await runSearchAutoCategoryBundle(args, category);
  attempts.push(...categoryBundle.attempts);
  acceptedResults.push(...categoryBundle.acceptedResults);
}
```

4. 再跑各个 engine
```js
for (const engine of engines) {
  const { quality, enrichedResult } = await runSearchAutoEngine(engine, args, siteTarget);
  attempts.push(buildSearchAutoAttempt(engine, enrichedResult, quality));
  if (quality green/yellow) acceptedResults.push(...usableResults)
}
```

5. 最后统一 buildSearchAutoResponse
```js
const final = buildSearchAutoResponse({ args, engines, attempts, acceptedResults, siteTarget });
```

这就是线上 search_auto 的真正内核。

==================================================
十一、线上版本的核心特征总结
==================================================

1. search_auto 是默认总入口，不是 source。
2. 它先做 query intent / category 路由。
3. 它能走 category bundle（例如 policy bundle）。
4. 它会再逐个 engine 尝试。
5. 每个尝试都有 quality_status / quality_reason。
6. 结果合并不是简单 dedupe，而是带分数、多源增强的 merge。
7. 最终响应会带 rich metadata：
   - attempts
   - sources
   - fallback_used
   - filtered_count
   - merged_count
   - deduped_count
   - quality_status
   - quality_reason

==================================================
十二、它和本地版本当前的主要差距
==================================================

本地 local-policy-agent 现在已经补上了：
- 官方 provider feed into auto
- sources
- attempts
- quality_status
- quality_reason

但和线上 Cloudflare 版本相比，仍然缺：

1. 更细的质量状态
- 线上：green / yellow / blocked / empty / red / junk / intent_mismatch 等
- 本地：目前只有 green / yellow

2. 运行统计
- 线上有：
  - fallback_used
  - filtered_count
  - merged_count
  - deduped_count
- 本地目前还没有这些

3. category bundle 路由深度
- 线上对 policy / jobs / flights / anime 都有专门 bundle
- policy 还有官方域 bundle（gov.cn / samr / ndrc / miit / moe）
- 本地目前 policy route 还只是国内优先 engines + 官方 provider feed-in

4. 更强的 official-policy reranking
- 线上已经会区分频道页 / 栏目页 / 汇总页 / 正文页
- 本地目前只是 official_or_policy_like / weak_homepage_like / unclassified_result

==================================================
十三、一句话总结
==================================================

Cloudflare 线上版本的 search_auto 本质上是：

- 一个带 query intent routing 的多源搜索编排器
- 一个带质量状态机的结果过滤器
- 一个带多源权重合并的重排器
- 一个会把 attempts / sources / fallback / counts 全部显式暴露给调用方的结果汇总器

它不是“选几个搜索引擎然后并起来”这么简单，而是一套：
- 路由
- 尝试
- 过滤
- 质量判断
- 合并
- 响应构造

的完整搜索层实现。
